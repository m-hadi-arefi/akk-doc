# اصول برنامه‌نویسی و مهندسی نرم‌افزار تمیز

## ۱. اصول پنج‌گانه SOLID
- **تک‌مسئولیتی (Single Responsibility Principle - SRP)**: یک کلاس یا ماژول باید فقط و فقط یک دلیل برای تغییر داشته باشد.
- **باز/بسته (Open/Closed Principle - OCP)**: موجودیت‌های نرم‌افزاری باید برای توسعه باز، اما برای تغییر بسته باشند.
- **جایگزینی لیسکوف (Liskov Substitution Principle - LSP)**: زیرنوع‌ها باید بدون برهم‌زدن درستی برنامه، قابل جایگزینی با نوع پایه خود باشند.
- **تفکیک اینترفیس‌ها (Interface Segregation Principle - ISP)**: کلاینت‌ها نباید مجبور شوند به رابط‌هایی وابسته شوند که از آن‌ها استفاده نمی‌کنند.
- **وارونگی وابستگی (Dependency Inversion Principle - DIP)**: ماژول‌های سطح بالا نباید به ماژول‌های سطح پایین وابسته باشند؛ هر دو باید به انتزاع‌ها وابسته باشند.

## ۲. انضباط کدنویسی تمیز (Clean Code)
- **نام‌گذاری معنادار**: اسامی باید بیانگر نیت واقعی متغیرها و متدها باشند (مانند `calculateVehicleDepreciation` به جای `calc`).
- **کوچک بودن توابع**: توابع باید تنها یک کار را انجام داده و از ایجاد اثرات جانبی پیش‌بینی‌نشده بپرهیزند.
- **مدیریت صحیح خطاها**: استفاده از پرتاب خطای صریح یا ساختارهای بازگشتی شفاف؛ هرگز نباید خطاها را بدون لاگ و مدیریت رها کرد.
- **تغییرناپذیری (Immutability)**: ترجیح ساختارهای داده تغییرناپذیر در لایه‌های دامنه جهت کاهش پیچیدگی‌های همزمانی.
