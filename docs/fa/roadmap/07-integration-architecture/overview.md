# معماری یکپارچه‌سازی

## هدف
این بخش نحوه اتصال سامانه‌ها و تبادل داده‌ها را در اکوسیستم شرکت آریان خودرو تعریف می‌کند. این سند لایه یکپارچه‌سازی، الگوهای ارتباطی، پروتکل‌ها و استانداردها را پوشش می‌دهد.

## اصول یکپارچه‌سازی
۱. **نرم‌افزارهای مدرن نباید مستقیماً به پیاده‌سازی‌های موروثی متکی شوند.**
۲. **کلیه یکپارچه‌سازی‌ها باید صریح، دارای مستندات رسمی و مجهز به مانیتورینگ باشند.**
۳. **خطاهای ارتباطی باید قابل کشف بوده و به صورت کنترل‌شده مدیریت شوند.**
۴. **هر دو الگوی همگام و ناهمگام معتبر هستند — انتخاب باید بر اساس ماهیت نیاز تجاری باشد.**
۵. **هر خط اتصال باید دارای متولی مشخص و سیاست مشخص برخورد با خطا باشد.**

## الگوهای یکپارچه‌سازی

### الگوهای همگام (Synchronous)
- **درخواست/پاسخ (Request/Response)**: فراخوانی آنی با مسدودسازی تا زمان دریافت پاسخ. مناسب برای استعلام‌های بلادرنگ.
- **درگاه API (API Gateway)**: نقطه ورودی متمرکز برای هدایت درخواست‌ها، محدودسازی نرخ و اعتبارسنجی توکن‌ها.

### الگوهای ناهمگام (Asynchronous)
- **صف پیام (Message Queue)**: تحویل پیام‌های مجزا بدون اتصال هم‌زمان فرستنده و گیرنده.
- **استریمینگ رویداد (Event Streaming)**: الگوی انتشار/اشتراک برای انتشار تغییرات وضعیت موجودیت‌ها در سراسر سازمان.
- **تبادل فایل دسته‌ای**: مناسب برای سیستم‌های موروثی بسیار قدیمی که فاقد هرگونه وب‌سرویس هستند.

### الگوی لایه ضدفساد (Anti-Corruption Layer)

```text
برنامه کاربردی مدرن
         │
         ▼
لایه یکپارچه‌سازی
         │
         ▼
آداپتور لایه ضدفساد (ACL)
         │
         ▼
سامانه موروثی (تدارک)
```

لایه ضدفساد مرزی امن و نفوذناپذیر میان سیستم‌های نوین و قدیمی ایجاد کرده و ترجمه مدل‌های دو طرف را بر عهده می‌گیرد.
