# معماری وضعیت مطلوب (Target Architecture)

## هدف
این بخش معماری هدف بوم نرم‌افزاری شرکت آریان خودرو را تشریح می‌کند. معماری هدف وضعیت نهایی مطلوبی است که سازمان در طول فرآیند تکامل گام‌به‌گام به سوی آن حرکت خواهد کرد.

## لایه‌های معماری هدف

```text
┌─────────────────────────────────────────────────────────────┐
│                     لایه کسب‌وکار                           │
│   فروش │ انبارداری │ تحویل خودرو │ CRM │ تحلیل داده │ خدمات │
├─────────────────────────────────────────────────────────────┤
│                      سکوی مرکزی                             │
│   هویت │ کنترل دسترسی │ درگاه API │ رویدادها │ داده مرجع     │
│                     سکوی داده تحلیلی                        │
├─────────────────────────────────────────────────────────────┤
│                   لایه یکپارچه‌سازی                         │
│   آداپتور تدارک │ آداپتور عاملیت‌ها │ آداپتورهای خارجی      │
├─────────────────────────────────────────────────────────────┤
│                 سامانه‌های موروثی و بیرونی                   │
│   سیستم تدارک │ پایگاه‌های داده قدیمی │ بانک‌ها             │
└─────────────────────────────────────────────────────────────┘
```

## مسئولیت‌های لایه‌ها

### لایه کسب‌وکار (Business Layer)
- مالکیت کامل منطق و فرآیندهای تجاری اختصاصی هر دامنه.
- مصرف قابلیت‌های مشترک سکوی مرکزی بدون اختراع مجدد چرخ.
- استفاده از آداپتورهای لایه یکپارچه‌سازی جهت دسترسی به داده‌های موروثی.
- عدم وابستگی به جزئیات پیاده‌سازی سیستم‌های قدیمی.

### سکوی مرکزی (Core Platform)
- ارائه خدمات و قابلیت‌های مشترک، امن و مقیاس‌پذیر سازمانی.
- فاقد هرگونه منطق اختصاصی کسب‌وکار.
- این سکو یک ERP نیست، بلکه بستر توانمندساز توسعه چابک است.

### لایه یکپارچه‌سازی (Integration Layer)
- اتصال نرم‌افزارهای مدرن به سامانه‌های قدیمی از طریق لایه‌های ضدفساد (ACL).
- ترجمه پروتکل‌ها و تبدیل ساختار داده‌های کهنه به استانداردهای نوین.
- ایزوله‌سازی پیچیدگی‌ها و بدهی‌های فنی موروثی از معماری جدید.

### سامانه‌های موروثی (Legacy Systems)
- استمرار فعالیت عملیاتی در طول فرآیند چندساله مهاجرت.
- محصور ماندن درون آداپتورهای اختصاصی تا زمان بازنشستگی کامل.

## اصول کلیدی معماری هدف
۱. **نرم‌افزارهای تجاری مالک منطق تجاری خود هستند.**
۲. **سکوی مرکزی صرفاً خدمات مشترک را ارائه می‌دهد.**
۳. **سیستم‌های موروثی هرگز مستقیماً دستکاری نمی‌شوند، بلکه درون آداپتور قرار می‌گیرند.**
۴. **ارتباطات میان لایه‌ها منحصراً از طریق اینترفیس‌های مستند و استاندارد انجام می‌شود.**
۵. **معماری در تمامی لایه‌ها کاملاً پایش‌پذیر و شفاف است.**
