# راهنمای انتخاب متدولوژی تحویل پروژه

## ماتریس تصمیم‌گیری

| ویژگی‌های پروژه | متدولوژی پیشنهادی |
|---|---|
| قابلیت‌های محصول با نیازمندی‌های در حال تکامل و بازخورد مداوم کاربران | **اسکرام (Scrum)** |
| پشتیبانی مداوم عملیاتی، تریاژ باگ‌ها و وظایف پایداری زیرساخت (SRE) | **کانبان (Kanban)** |
| ریسک بالای معماری، هسته سکوی مرکزی و پایه‌های داده | **RUP (با تمرکز بر فاز Elaboration)** |
| محاسبات پیچیده مالی و بانکی با الزام به کد بدون خطا | **برنامه‌نویسی مفرط (XP)** |
| قرارداد برون‌سپاری با محدوده کاملاً ثابت و تسویه‌حساب بر اساس فاز | **آبشاری / گیت‌های مرحله‌ای پیش‌بینانه** |
| برنامه‌های کلان چندسازمانی با نیاز به هدایت ارشد مدیریتی | **ترکیبی (حاکمیت PRINCE2/PMI + اسپرینت‌های چابک)** |

## الگوریتم تصمیم‌گیری متدولوژی
```text
آیا نیازمندی‌ها در حین توسعه تغییر خواهند کرد؟
 ├─► بله ──► آیا ماهیت کار دسته‌ای (اسپرینت) است یا جریان مداوم؟
 │            ├─► دسته‌ای ──────► اسکرام (SCRUM)
 │            └─► مداوم ────────► کانبان (KANBAN)
 │
 └─► خیر ──► آیا ریسک فنی و معماری پروژه بالا است؟
              ├─► بله ──────────► متدولوژی RUP (تمرکز بر فاز Elaboration)
              └─► خیر ──────────► روش خطی مرحله‌ای (Stage-Gate)
```
