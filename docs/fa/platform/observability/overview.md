# مشخصات سکوی پایش‌پذیری (Observability)

## مسئله
در گذشته کشف خطاهای سیستم نیازمند اتصال دستی SSH به سرورها و جستجوی کلمات در فایل‌های متنی لاگ بود که این امر زمان ترمیم خرابی‌ها (MTTR) را به شدت بالا می‌برد.

## هدف
ایجاد دیده‌بانی و پایش‌پذیری سرتاسری و بلادرنگ برای تمامی برنامه‌ها، کانتینرها، سرویس‌های سکوی مرکزی و اجزای زیرساختی شرکت آریان خودرو.

## سه ستون اصلی پایش‌پذیری (Three Pillars)

| ستون | ابزار و استاندارد | هدف عملیاتی |
|---|---|---|
| **سنجه‌ها (Metrics)** | Prometheus + Grafana | ردیابی سلامت سامانه، نرخ فراخوانی‌ها، خطاهای سیستم، تاخیرهای صدک ۹۵ و ۹۹ و مصرف منابع سرور. |
| **لاگ‌ها (Logs)** | Fluentbit + OpenSearch | ثبت ساخت‌یافته متمرکز به صورت JSON با فیلدهای استاندارد (`trace_id`, `service`, `level`, `msg`). |
| **ردگیری‌ها (Traces)** | OpenTelemetry + Jaeger | ردگیری سرتاسری جریان اجرای تراکنش‌ها میان درگاه‌ها، سرویس‌ها و بانک‌های اطلاعاتی. |

## فرمت استاندارد لاگ‌ها
تمامی میکروسرویس‌ها باید خروجی لاگ خود را با ساختار استاندارد JSON روی `stdout` منتشر کنند:
```json
{
  "timestamp": "2026-09-03T10:15:30Z",
  "level": "ERROR",
  "service": "workshop-service",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "span_id": "00f067aa0ba902b7",
  "message": "Failed to reserve spare part SKU-994",
  "error": "InsufficientStockException"
}
```
