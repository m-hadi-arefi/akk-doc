# مشخصات سکوی داده (Data Platform)

## مسئله
پایگاه‌های داده عملیاتی (OLTP) تحت بار سنگین پرس‌وجوهای تحلیلی و گزارش‌گیری‌های حجیم دچار افت شدید کارایی می‌شدند که این امر زمان پاسخگویی سامانه‌ها را به شدت کاهش داده و امکان گزارش‌گیری بلادرنگ هوش تجاری را سلب می‌کرد.

## هدف
جداسازی بارهای کاری تحلیلی، هوش تجاری و یادگیری ماشین از پایگاه‌های داده عملیاتی از طریق معماری مدرن دریاچه داده (Lakehouse).

## خط لوله معماری داده

```text
پایگاه‌های داده عملیاتی (PostgreSQL / MySQL / تدارک)
                  │
                  ▼ (دریافت بلادرنگ تغییرات - Debezium CDC)
گذرگاه داده Kafka
                  │
                  ▼ (موتورهای استریمینگ Vector / Spark)
ذخیره‌ساز تحلیلی (ClickHouse / MinIO Parquet Lakehouse)
                  │
                  ▼
داشبوردهای هوش تجاری و تحلیل‌های مدیریتی (Metabase / Superset)
```

## مسئولیت‌ها
- جمع‌آوری بلادرنگ تغییرات (CDC) از کلیه پایگاه‌های داده رابطه‌ای سازمان.
- اجرای خط لوله‌های پالایش، تجمیع و انتقال خودکار روزانه داده‌ها.
- تغذیه داشبوردهای هوش تجاری، گزارش‌های تطبیق مالی و شاخص‌های فروش و خدمات.
