# مشخصات سرویس کنترل دسترسی (Authorization Service)

## مسئله
در سیستم‌های سنتی، بررسی مجوزهای دسترسی کاربران مستقیماً درون کوئری‌های دیتابیس یا دکمه‌های رابط کاربری هاردکد می‌شد که حسابرسی امنیتی سیستم را ناممکن و تغییر نقش‌ها را با خطای انسانی مواجه می‌ساخت.

## هدف
ارائه موتور متمرکز و سیاست‌محور ارزیابی دسترسی‌ها برای کلیه سرویس‌ها و برنامه‌های تجاری سراسر سازمان آریان خودرو.

## مسئولیت‌ها
- مدیریت متمرکز سیاست‌های امنیتی (Policy Administration Point - PAP).
- ارزیابی بسیار پرسرعت درخواست‌های دسترسی (Policy Decision Point - PDP).
- پشتیبانی از کنترل دسترسی بر مبنای نقش (RBAC) برای نقش‌های استاندارد سازمانی.
- پشتیبانی از کنترل دسترسی بر مبنای خصوصیات (ABAC) برای محدودیت‌های زمینه‌ای (نظیر عاملیت کاربر، سقف مبالغ مالی، ساعت کاری).

## عدم مسئولیت‌ها
- احراز هویت اولیه کاربران (به [سرویس هویت](../identity/overview.md) واگذار شده است).
- نگهداری پرونده‌های کسب‌وکاری و مالی سازمان.

## معماری و واسط‌های ارتباطی
- **الگوی معماری**: نقاط اعمال سیاست (PEP) در درگاه API و سرویس‌ها تعبیه شده و نقطه تصمیم‌گیری (PDP) را از طریق gRPC با سرعت بالا فراخوانی می‌کنند.
- **رابط ارزیابی PDP (پروتکل gRPC)**:
  `CheckAccess(subject_id, resource_type, resource_id, action, context_attributes) -> ALLOW / DENY`

## رویدادهای منتشرشده در پلتفرم
- `authz.policy.updated`
- `authz.access.denied_anomaly`
