# تحویل چابک و ریتم اسپرینت‌های دوهفته‌ای (Agile Delivery)

## خلاصه مدیریتی
پروژه‌های نرم‌افزاری سنتی آبشاری (Waterfall) به این دلیل در سازمان‌ها شکست می‌خورند که نیازمندی‌ها بسیار سریع‌تر از فرآیند طولانی برنامه‌نویسی تغییر می‌کنند. شرکت آرین خودرو بر پایه **تواتر اسپرینت‌های دوهفته‌ای** و متدولوژی **چابک دومسیره (Dual-Track Agile)** فعالیت می‌کند. با اجرای هم‌زمان «شناخت مداوم» در کنار «تحویل مداوم مهندسی»، تیم همواره بر روی نیازهای اعتبارسنجی‌شده تمرکز داشته و نرم‌افزار کارا را بلافاصله در اختیار کاربران عملیاتی قرار می‌دهد.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              مدل عملیاتی چابک دومسیره (Dual-Track Agile)                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  مسیر ۱: شناخت مداوم (مدیر محصول + تحلیل‌گر کسب‌وکار + معمار ارشد سیستم)               │
│  • مصاحبه با پرسنل  • کشف حالت‌های خاص  • پروتوتایپ صفحات وب  • پالایش داده‌های واقعی  │
│          │                                                                             │
│          ▼ داستان‌های کاربر آماده توسعه همراه با سناریوهای تست (شرایط DoR)             │
│                                                                                        │
│  مسیر ۲: تحویل مداوم مهندسی (مهندسان تیم چابک نرم‌افزار)                               │
│  • کدنویسی ماژول‌ها • تست‌های خودکار  • بازبینی کد در گیت  • استقرار در محیط تستی       │
│          │                                                                             │
│          ▼ نرم‌افزار تست‌شده و قابل بهره‌برداری عملیاتی (شرایط DoD)                    │
│  جلسه دموی دوهفته‌یک‌بار برای مدیرعامل و مدیران (بدون اسلاید؛ نمایش زنده نرم‌افزار)    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## ۱. جدول زمانی ریتم اسپرینت‌های دوهفته‌ای

| روز اسپرینت | عنوان رویداد | هدف و شرکت‌کنندگان رویداد |
| :--- | :--- | :--- |
| **روز اول (شنبه ساعت ۰۹:۰۰)** | **جلسه برنامه‌ریزی (Planning)**| تعهد تیم به داستان‌های کاربری اولویت‌داری که شرایط DoR را دارند. |
| **هر روز (ساعت ۰۹:۱۵ تا ۰۹:۳۰)**| **جلسه سرپایی روزانه (Standup)**| هماهنگی ۱۵ دقیقه‌ای: دیروز چه شد، امروز چه می‌شود، موانع چیست. |
| **روز پنجم (چهارشنبه ساعت ۱۴:۰۰)**| **پالایش بک‌لاگ (Refinement)** | آماده‌سازی و شفاف‌سازی تسک‌های اسپرینت بعدی همراه با خبره کسب‌وکار. |
| **روز دهم (چهارشنبه ساعت ۱۵:۰۰)**| **دموی زنده (Review & Demo)** | نمایش زنده کارکرد نرم‌افزار برای مدیرعامل، مدیران واحدها و پرسنل. |
| **روز دهم (چهارشنبه ساعت ۱۶:۳۰)**| **جلسه بازنگری (Retrospective)**| بررسی نقادانه و بدون سرزنش فرآیندها جهت بهبود همکاری در اسپرینت بعد. |

## ۲. گیت‌های ارزیابی کیفیت: شرایط ورود (DoR) و شرایط خروج (DoD)

### شرایط ورود به اسپرینت (Definition of Ready - DoR)
هیچ تسکی وارد فرآیند توسعه نمی‌شود مگر آنکه:
۱. ارزش تجاری و نتیجه مورد انتظار آن به زبانی شفاف و بدون ابهام بیان شده باشد.
۲. معیارهای پذیرش در قالب استاندارد سناریوهای مشخص تعریف شده باشند.
۳. فرم‌های کاربری توسط نماینده خبره دپارتمان بازبینی و تأیید شده باشند.
۴. ساختار جداول دیتابیس و پیش‌نیازهای وب‌سرویسی آن شفاف و آماده باشد.

### شرایط خروج و تحویل نهایی (Definition of Done - DoD)
هیچ قابلیتی به محیط پروداکشن ارسال نمی‌شود مگر آنکه:
۱. ۱۰۰٪ آزمون‌های خودکار واحد و یکپارچگی در گیت‌لب پاس شوند.
۲. کدها آزمون‌های امنیتی و استانداردهای کیفی را بدون خطا طی کنند.
۳. حداقل توسط دو مهندس ارشد بازبینی و تأیید شده باشد.
۴. در محیط آزمایشی با داده‌های واقعی ناشناس‌سازی‌شده تست شده باشد.
۵. نماینده کسب‌وکار رسماً عملکرد آن را به صورت زنده تأیید کرده باشد.
۶. راهنمای کاربری و مستندات به دو زبان انگلیسی و فارسی منتشر شده باشد.

## نتیجه‌گیری و گیت تصمیم‌گیری
- **تصمیم‌های کلیدی:** تعهد سازمانی به رعایت بی‌چون‌وچرای DoR و DoD؛ ممنوعیت ارائه گزارش با اسلاید پاورپوینت در جلسات دمو.
- **پرسش‌های باز:** تنظیم تقویم کاری اسپرینت‌ها بر اساس تعطیلات رسمی و دوره‌های حساس مالی سازمان.
