# معماری نرم‌افزار، سکوی مرکزی و مهندسی داده (Digital Architecture)

## خلاصه مدیریتی
این بخش شالوده فنی و استانداردهای مهندسی سکوی مرکزی شرکت آرین خودرو را تدوین می‌کند. ما هم شکنندگی نرم‌افزارهای بسته‌بندی‌شده غیرقابل نگهداری خارجی را رد می‌کنیم و هم از پیچیدگی‌های زودرس معماری میکروسرویس دوری می‌جوییم. در عوض، یک معماری مستحکم **مونولیت ماژولار (Modular Monolith)** درون‌سازمانی، الگوهای همزیستی ایمن با سیستم تدارک از طریق **لایه ضدفساد (ACL)**، پایپ‌لاین‌های داده‌های مرجع یکپارچه و برنامه مدون بازنشستگی فایل‌های اکسل سایه را مستقر می‌سازیم.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                ارکان فنی و مهندسی سکوی مرکزی                           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  • سبک معماری       ◄ مونولیت ماژولار عمل‌گرایانه (پکیج استقرار واحد، مرزهای مستقل)   │
│  • پشته فناوری      ◄ تایپ‌اسکریپت، Go، دیتابیس PostgreSQL، ردیس، داکر و GitLab CI     │
│  • اتصال به سیستم قدیم◄ لایه ضدفساد (دیتابیس شبیه‌سازی‌شده فقط‌خواندنی و همگام‌سازی)   │
│  • مدیریت داده‌ها   ◄ رکورد طلایی داده‌های شاسی خودرو (VIN) و کاتالوگ استاندارد قطعات │
│  • بازنشستگی اکسل‌ها ◄ دستورالعمل گام‌به‌گام جایگزینی اکسل‌های سایه با نرم‌افزار سازمانی│
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## نتیجه‌گیری و گیت تصمیم‌گیری
- **تصمیم‌های کلیدی:** انتخاب مونولیت ماژولار به عنوان الگوی استاندارد توسعه؛ الزام به پوشش ۱۰۰ درصدی آزمون‌های خودکار برای آداپتورهای مالی.
- **پرسش‌های باز:** انتخاب محل ذخیره‌سازی آبجکت‌ها (MinIO محلی در برابر کلود) برای ذخیره تصاویر خودروها و PDF اسناد گمرک.
- **اقدام‌های بعدی:** مطالعه سند [استراتژی نرم‌افزار و مهندسی](./software-strategy) جهت مشاهده اصول برنامه‌نویسی تیم.
