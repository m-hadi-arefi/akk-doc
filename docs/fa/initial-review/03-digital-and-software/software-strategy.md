# استراتژی مهندسی نرم‌افزار و استانداردهای باز (Software Strategy)

## خلاصه مدیریتی
استراتژی نرم‌افزاری شرکت آرین خودرو نقطه پایانی بر دهه‌ها وابستگی به پیمانکاران ناشناخته، نرم‌افزارهای بسته تجاری و اسکریپت‌های ناپایدار بدون ورژن است. ما توانمندی مهندسی نرم‌افزار درون‌سازمانی را بر پایه پشته‌های نرم‌افزاری استاندارد و متن‌باز، استانداردهای سخت‌گیرانه برنامه‌نویسی، تست‌های خودکار و مالکیت شفاف سورس‌کدها مستقر می‌سازیم.

```text

│                              اصول مهندسی و پشته فناوری منتخب                           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  • زبان و محیط اجرا   ◄ نود جی‌اس (TypeScript LTS) و زبان Go برای خطوط لوله پرسرعت      │
│  • رابط کاربری وب     ◄ ری‌اکت مدرن (React)، تایپ‌اسکریپت و تیلویند (Tailwind CSS)      │

└────────────────────────────────────────────────────────────────────────────────────────┘
```

## ۱. بیانیه اصول مهندسی نرم‌افزار سازمان
۱. **سورس‌کد، دارایی استراتژیک سازمان است:** هر خط کدی که برای آرین خودرو نوشته می‌شود باید در مخازن گیت تحت کنترل شرکت ثبت گردد، دارای تست خودکار باشد و از الگوهای مستندسازی استاندارد تبعیت کند.
۲. **صراحت و شفافیت بر جادوگری ارجحیت دارد:** ما کدهای ساختاریافته و دارای تایپ صریح (TypeScript/Go) را به فریم‌ورک‌های جادویی و غیرشفاف ترجیح می‌دهیم. هر مهندس جدید باید بتواند محیط توسعه را در کمتر از ۱۵ دقیقه راه‌اندازی کند.
۳. **ممنوعیت اعمال تغییرات مستقیم در دیتابیس عملیاتی:** هیچ برنامه‌نویس یا مدیری حق ندارد مستقیماً دستورات SQL ویرایشی در دیتابیس پروداکشن اجرا کند. کلیه تغییرات از طریق اسکریپت‌های نسخه‌بندی‌شده Migration و در پایپ‌لاین CI/CD اعمال می‌شوند.
۴. **گیت‌های خودکار ارزیابی کیفیت:** هیچ کدی به شاخه اصلی (Main) مرج نمی‌شود مگر آنکه:
   - تمام آزمون‌های واحد (Unit Tests) و یکپارچگی (Integration) با موفقیت پاس شوند.
   - خطاهای استانداردهای کدنویسی (Linter) به صفر برسد.
   - حداقل دو مهندس ارشد کد را بررسی و به صورت سیستمی تأیید کرده باشند.

## ۲. پشته فناوری‌های استاندارد سکوی مرکزی

| لایه معماری | فناوری منتخب | منطق انتخاب و ارزش‌آفرینی برای سازمان |
| :--- | :--- | :--- |
| **سرویس‌های بک‌اند** | Node.js (TypeScript) و Go | سرعت بالای توسعه منطق کسب‌وکار با نود؛ کارایی فوق‌العاده Go در پردازش فایل‌های حجیم و OCR. |
| **رابط‌های کاربری وب**| React 18+ و TypeScript | غنی‌ترین اکوسیستم توسعه نرم‌افزار، کتابخانه‌های استاندارد و عملکرد روان رابط‌های کاربری. |
| **پایگاه داده اصلی** | PostgreSQL 16+ | پشتیبانی قدرتمند از تراکنش‌های مالی (ACID)، ایندکس‌های پیشرفته JSONB و هزینه‌های لایسنس صفر. |
| **حافظه موقت و کش** | Redis 7+ | مدیریت نشست‌های کاربران، کنترل نرخ ترافیک APIها و قفل‌های توزیع‌شده رزرواسیون شاسی در انبار. |
| **ذخیره‌سازی فایل‌ها** | MinIO (سازگار با S3) | پروتکل استاندارد ذخیره تصاویر بازرسی خودروها، فاکتورهای گمرک و اسناد گارانتی. |
| **پروتکل‌های API** | RESTful JSON و Webhooks | ساختار ساده، خوانا برای انسان، خطایابی سریع و پشتیبانی در تمام مرورگرها و سامانه‌ها. |

## ۳. نظام مستندسازی معماری و ثبت تصمیمات (ADR)
هر تصمیم فنی تأثیرگذار بر سیستم (انتخاب درایور دیتابیس، تغییر ساختار APIها، اضافه کردن لایه کش) باید در قالب یک **سند تصمیم‌گیری معماری (ADR)** ثبت شود. این اسناد هفتگی در شورای معماری بازبینی شده و در مخزن گیت ذخیره می‌گردند.

---

## نتیجه‌گیری و گیت تصمیم‌گیری
- **تصمیم‌های کلیدی:** انتخاب پشته تایپ‌اسکریپت و Go به عنوان استاندارد انحصاری؛ اعلام PostgreSQL به عنوان پایگاه داده رسمی سکوی مرکزی.
- **پرسش‌های باز:** مشخصات نهایی سرورهای فیزیکی جهت راه‌اندازی کلاستر افزونه‌پذیر (HA) پایگاه داده PostgreSQL.
- **اقدام‌های بعدی:** مطالعه سند [معماری مونولیت ماژولار](./modular-monolith) جهت مشاهده نحوه تفکیک ماژول‌های پلتفرم.
