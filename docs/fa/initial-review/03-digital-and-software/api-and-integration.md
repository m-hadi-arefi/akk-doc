# معماری API، درگاه ارتباطی و استانداردهای یکپارچگی (API Architecture)

## خلاصه مدیریتی
چابکی یک سازمان نوین در گرو رابط‌های برنامه‌نویسی استاندارد، امن و مستند (APIs) است. در گذشته شرکت آرین خودرو برای تبادل داده میان واحدها به انتقال دستی فایل‌ها یا اجرای اسکریپت‌های ناپایدار در شبکه محلی تکیه داشت. این سند **معماری درگاه یکپارچه‌سازی و APIهای سازمانی** را تعریف می‌کند. استانداردهای طراحی RESTful، مدل‌های پیام‌رسانی وب‌هوک، توپولوژی درگاه Gateway، سیاست‌های کنترل ترافیک و الزام به مستندسازی با OpenAPI 3.0 در این سند تبیین شده‌اند.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              توپولوژی درگاه مدیریت و مسیریابی APIها                     │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  مصرف‌کنندگان خارجی (نمایندگی‌ها، نرم‌افزار موبایل انبار، کارگزاران گمرک، داشبوردهای BI)│
│          │                                                                             │

│  │   درگاه مرکزی API و معکوس پروکسی (API Gateway)                                  │  │
```

## ۱. استانداردهای توسعه APIهای RESTful در سازمان
کلیه وب‌سرویس‌های پلتفرم از استانداردهای یکنواخت و قابل پیش‌بینی تبعیت می‌کنند:
- **آدرس‌دهی منبع‌محور:** استفاده از اسامی جمع در مسیرها (نظیر `/api/v1/vehicles` و `/api/v1/dealers/{id}/warranty-claims`).
- **افعال استاندارد HTTP:** متد `GET` برای خواندن، `POST` برای ایجاد، `PUT` برای بازنویسی کامل، `PATCH` برای ویرایش جزئی، و `DELETE` برای بایگانی.
- **ساختار استاندارد پیام‌های خطا:** کلیه خطاها ساختار یکپارچه JSON همراه با کد خطای ماشین‌خوان و شناسه پیگیری بازمی‌گردانند:
  ```json
  {
    "error": {
      "code": "VIN_ALREADY_RESERVED",
      "message": "خودرو با این شماره شاسی قبلاً برای نمایندگی دیگری رزرو شده است.",
      "correlationId": "req-98f2b34a-20260904"
    }
  }
  ```
- **سیاست نسخه‌بندی:** نسخه در مسیر URL قید می‌شود (`/api/v1/`). هرگونه تغییر ناسازگار نیازمند ایجاد نسخه جدید و مهلت انتقال حداقل ۶ ماهه است.

## ۲. سرویس وب‌هوک و رویدادهای ناهمگام (Webhooks)
برای ارتباط با شرکای تجاری بیرونی و وظایف زمان‌بر پس‌زمینه، پلتفرم دارای موتور وب‌هوک است:
- **امضای رمزنگاری‌شده داده‌ها:** هر درخواست وب‌هوک حاوی امضای HMAC-SHA256 در هدر `X-Signature-SHA256` است تا دریافت‌کننده از اصالت پیام اطمینان یابد.
- **سیستم تلاش مجدد خودکار:** در صورت عدم پاسخ‌گویی سرور مقصد، ارسال پیام با تأخیر تصاعدی طی ۲۴ ساعت تکرار می‌شود.

---

## ۳. درگاه‌های اختصاصی شبکه نمایندگی‌های مجاز
پلتفرم وب‌سرویس‌های معتبر و مستندی برای نمایندگی‌ها ارائه می‌دهد:
- `POST /api/v1/dealers/orders/parts` — ثبت سفارش خرید قطعات یدکی از انبار مرکزی.
- `POST /api/v1/dealers/warranty/claims` — بارگذاری فاکتورهای گارانتی به همراه عکس قطعات تعویض‌شده.
- `GET /api/v1/dealers/inventory/available` — استعلام لیست خودروهای آزاد و قابل تخصیص در انبار.

## نتیجه‌گیری و گیت تصمیم‌گیری
- **تصمیم‌های کلیدی:** الزام به تعریف قراردادهای OpenAPI 3.0 پیش از برنامه‌نویسی؛ استقرار کنترل نرخ دسترسی و احراز هویت توکن در گیت‌وی.
- **پرسش‌های باز:** تعیین سقف مجاز فراخوانی در دقیقه (Rate Limit) برای سیستم‌های نرم‌افزاری نمایندگی‌ها.
- **اقدام‌های بعدی:** مطالعه سند [برنامه مهاجرت از فناوری سایه](./shadow-it-migration) جهت بررسی مسیر بازنشستگی اکسل‌ها.
